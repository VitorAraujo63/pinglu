A gramatica do Pinglu, escrita por extenso no primeiro modulo.
Nao esta fatorada -- fatoracao fica para o modulo futuro de gramaticas
livres de contexto, que retoma este arquivo e registra cada transformacao
com a forma anterior ao lado da forma final. As tres producoes que estavam
marcadas PENDENTE (funcDecl, forStmt, pineachStmt) foram fechadas depois do
feedback recebido; a decisao de cada uma, com a alternativa descartada,
esta em docs/01_recorte.md e docs/04_escolher_e_formas.md.

--- Programa ---

program     := decl* ;
decl        := varDecl | funcDecl | formaDecl | stmt ;

varDecl     := TIPO ID "=" expr ";" ;
TIPO        := "int" | "string" | "char" | "decimal" | "float" | "list"
             | ID ;
             -- ID aqui cobre um tipo-forma declarado por formaDecl
             -- (ex.: "Geometria f = circulo(3.0);"), ver
             -- docs/04_escolher_e_formas.md.

funcDecl    := "func" ID "(" params? ")" block ;
params      := param ( "," param )* ;
param       := TIPO ID ;
             -- sem tipo de retorno declarado (fixado em
             -- descricao_linguagem.md: "Funcoes precisarao declarar o tipo
             -- de retorno? R: Nao"); "return" e um stmt normal, nao parte
             -- da assinatura.

formaDecl   := "forma" ID "{" variante+ "}" ;
variante    := ID "(" params? ")" ";" ;
             -- declara um tipo-soma fechado: ID (o nome do tipo-forma) e
             -- cada variante com seus campos tipados. Ver
             -- docs/04_escolher_e_formas.md.

--- Instrucoes ---

stmt        := ifStmt | whileStmt | forStmt | pineachStmt | escolherStmt
             | returnStmt | printStmt | exprStmt | block ;

block       := "{" decl* "}" ;

ifStmt      := "if" "(" expr ")" stmt ( "else" stmt )? ;
whileStmt   := "while" "(" expr ")" stmt ;

forStmt     := "for" "(" ( varDecl | exprStmt | ";" ) expr? ";" expr? ")" stmt ;
             -- estilo C: inicializacao (declaracao ou expressao), condicao,
             -- passo -- todas opcionais, mas os ";" internos sao
             -- obrigatorios. Ex.: for (int i = 0; i != 10; i = i + 1) { ... }

pineachStmt := "pineach" "(" ID "in" expr ")" stmt ;
             -- ID e o nome da variavel de iteracao, ligada a cada elemento
             -- da lista avaliada por expr; escopo dela e o corpo do
             -- pineach, mesma regra de docs/01_recorte.md
             -- "Escopo lexico e vinculacao de nomes".

escolherStmt := "escolher" expr "{" clausula+ "}" ;
clausula      := ID "(" identList? ")" "->" stmt ;
identList     := ID ( "," ID )* ;
             -- ver docs/04_escolher_e_formas.md para a verificacao de
             -- cobertura que roda sobre esta producao antes da geracao de
             -- bytecode -- a gramatica so descreve a forma reconhecivel,
             -- nao a checagem de exaustao (essa e semantica, nao sintaxe).

returnStmt  := "return" expr? ";" ;
printStmt   := "print" "(" expr ")" ";" ;
exprStmt    := expr ";" ;

--- Expressoes ---
-- Precedencia crescente conforme desce nas producoes, do jeito que o
-- material do professor recomenda: a ordem das producoes E a precedencia,
-- sem tabela separada.

expr        := orExpr ;
orExpr      := andExpr ( "||" andExpr )* ;
andExpr     := eqExpr ( "&&" eqExpr )* ;
eqExpr      := relExpr ( ( "==" | "!=" ) relExpr )? ;
relExpr     := addExpr ( ( "<" | ">" ) addExpr )? ;
addExpr     := primary ( ("+" | "-") primary )* ;
primary     := ID | NUMBER | STRING | CHAR
             | ID "(" argList? ")"
             | "[" argList? "]"
             | "(" expr ")" ;
argList     := expr ( "," expr )* ;
             -- "[" argList "]" e o literal de lista (ex.: [10, 20, 30]),
             -- fechado como consequencia de escrever o exemplo do
             -- pineachStmt -- ver docs/01_recorte.md.
             -- "ID (" argList ")" cobre tanto chamada de funcao quanto
             -- construcao de variante de forma (ex.: circulo(3.0)) -- as
             -- duas so se distinguem na analise semantica, verificando se
             -- ID nomeia um funcDecl ou uma variante de formaDecl. A
             -- gramatica nao precisa dessa distincao para reconhecer a
             -- cadeia.

--- Onde cada nivel da hierarquia de Chomsky comparece ---

O programa inteiro (program/decl/stmt/block) e livre de contexto (tipo 2):
"block" se refere a "decl", que pode conter outro "block" -- e esse
aninhamento e o que exige pilha para reconhecer, e nenhum automato finito
reconhece sozinho. As expressoes (expr e seus niveis) tambem sao livres de
contexto por causa dos parenteses em "primary", mas cada TOKEN individual
(um ID, um NUMBER, uma palavra-chave) e reconhecido por um padrao regular
(tipo 3) -- e e essa a fronteira entre o que o analisador lexico resolve
sozinho e o que precisa do analisador sintatico.
